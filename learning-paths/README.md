# 运维学习路线

面向准备入行、转行或补齐基础的学习者，按「阶段 → 能力模块 → 学习节点」组织运维知识，说明先学什么、掌握到什么程度，以及如何用实践检查自己。

[打开学习路线](./index.html) · [返回专题笔记目录](../index.html)

路线负责安排学习顺序，`topics/` 中的笔记负责深入讲解。建议先完成 Linux 基础，再按目标岗位选择分支，不需要学完全部路线才开始实践。

共 **37 个阶段、186 个模块、766 个学习节点**。总数包含 Python、Go 两种备选语言的专属节点；运维开发两分支合计 112 个，页面根据主修选择显示对应内容。

Linux 路线为 **7 阶段**，其余五条路线各 6 阶段。Linux 第 5 阶段“数据库与缓存运维”包含 **11 个模块、51 个节点**，从数据职责、MySQL 读写和实例管理，延伸到锁与复制、备份恢复、Redis 权限与持久化、缓存失效、监控和交接。第 7 阶段增加 **Ansible 批量自动化的 9 个节点**，与 Bash、Git 和运行手册衔接。原有 MySQL / Redis 节点 ID 与进度存储位置保持不变。

“入门”相对于当前路线，云运维、Kubernetes、SRE 和开发路线都列有前置要求。“入门 / 进阶 / 选修”表示优先级，“了解 / 会用 / 会排障”表示掌握深度。

## 使用方法

1. 选择路线，先看标题下的前置能力说明。
2. 点击模块名称展开节点，点击“详情”查看模块范围和综合练习。
3. 用“定位阶段”聚焦当前学习阶段；使用搜索查找工具或能力。
4. 按需要筛选入门必修、进阶能力或选修内容。搜索和筛选会自动展开匹配模块。
5. 用“前置自测与跳学”定位第一个尚不能独立完成的阶段；自测不自动修改完成状态。
6. 打开[贯穿实验室](./labs/index.html)，从可运行应用开始，沿六条路线复用实验与验收记录。
7. 在节点详情写下验收笔记；完成验收后标记“学习中”或“已完成”，模块会汇总子节点进度。

可观测性主要在 **SRE 第 2 阶段**，包含 Prometheus/PromQL、Alertmanager、Grafana、OpenTelemetry、日志平台、指标存储和链路查询。**Linux 第 4 阶段**补充 Nginx、消息队列、RabbitMQ、Kafka、服务发现与 Consul；第 5 阶段独立讲解 MySQL 与 Redis，第 6 阶段提供 Zabbix 选修。**Kubernetes 第 5 阶段**包含监控 Operator 与 CRD 接入。

命令组合、重定向、退出码和文本过滤已提前到 Linux 第 1 阶段；完整 Bash 脚本在第 7 阶段，与 Git、Ansible 批量自动化和交接手册一起学习。消息队列与服务发现基础归为进阶，先完成基础网站、监控与恢复。Linux 新增主机安全、启动救援、网络诊断及数据库进阶；Kubernetes 补故障域分布、控制面和存储生命周期；DevOps 补配置发布与交付系统恢复；SRE 补依赖相关故障、恢复对账和压测口径。

同类产品按岗位和实验条件选择，例如 RabbitMQ / Kafka、Loki / ELK、Jaeger / Tempo，不要求同时维护所有产品。

运维开发已接入 [AI 原生 SDLC 手册](../topics/delivery/ai-native-sdlc/README.md)中的方法，共 4 个模块、16 个节点：第 1 阶段的需求、规格与实现计划，第 2 阶段的仓库上下文与 AI 协作，第 6 阶段的 AI 反馈评估和受控交付闭环。需求与失败契约属于基础能力，其余主要为进阶；AI 工具按实际环境选择，学习目标不依赖单一厂商。

## 本地打开

在仓库根目录启动静态服务：

```bash
python3 -m http.server 8000
```

访问 <http://127.0.0.1:8000/learning-paths/>。

也可直接打开 `learning-paths/index.html`。页面不需要构建、后端或外部运行库；仓库内笔记链接依赖当前目录结构。HTTP 方式更适合长期记录学习进度。

## 学习进度

进度保存在当前浏览器的 `localStorage` 中，不会上传或自动跨设备同步。相同协议、主机与端口下，从临时页面进入正式页面会继续使用原有记录；更换端口、浏览器或切换文件打开方式，不保证共享进度。

“进度备份”可导出六路线 JSON，包含两种语言、验收笔记和旧模块记录。在另一浏览器导入时先预览，再合并：同名记录以导入文件为准，未包含的记录保留。建议先导出当前记录。笔记最多 2000 字符，勿保存密钥或真实用户数据；备份文件不要公开上传。

运维开发的 Python / Go 专属节点分别记录状态，切换主修不会删除另一分支的记录。旧版模块级状态保留供复核，不会自动把拆分后的全部子节点标为已完成。

## 内容与资料边界

这是一份带实践目标的学习导航。`labs/` 提供基础应用、Compose、systemd 与 Kubernetes 起始配置、受控故障、隔离备份恢复工具和验收模板；尚未为每个高级节点提供完整实验包、标准答案或自动评分。部分资料链接指向相关专题或官方产品目录，需要按节点范围选择章节。暂无专属资料的节点会明确提示。

学习顺序和验收标准是本项目的教学设计，并不等于厂商认证大纲或岗位录用标准。需要云账号、集群或故障注入的练习，应在自己授权、可恢复的实验环境完成。

路线图的视觉组织参考 [roadmap.sh Linux](https://roadmap.sh/linux) 与 [DevOps](https://roadmap.sh/devops)，中文内容、层级、优先级和验收任务独立整理。

## 维护结构

```text
learning-paths/
├── index.html              # 页面入口
├── styles.css              # 页面与路线图样式
├── app.js                  # 布局、筛选、详情、自测和本地进度
├── progress-store.js       # 备份格式校验与合并恢复
├── labs/                   # 可运行应用、配置、实验指南与测试
├── tests/                  # 路线数据、资料与进度兼容验证
├── data/
│   ├── linux-route.js      # Linux 阶段与模块
│   ├── routes-content.js   # 其余五条路线的阶段与模块
│   └── skills/             # 细分节点、补充模块及分类
├── assets/                 # README 使用的实际页面截图
└── README.md
```

- 阶段与模块没有固定数量限制，布局根据内容计算。
- `data/skills/schema.js` 定义节点字段；各路线文件保存目标与验收任务；`catalog.js` 组合最终数据并设置优先级和语言分支。
- 节点 ID 用于保存进度，不应因排序或文案调整而变更。前移的三个 Bash 节点保留 `bash.*` ID，归属变为 `shell-basics`。
- 修改内容后核对统计、资料路径和六路线交互；视觉变化后重新拍摄截图。
- 本目录是独立学习导航，不由 `scripts/build-roadmaps.sh` 生成，也不计入根目录的专题笔记和标准 Roadmap 数量。
